# CodeScene configuration for personal-website-spike

This directory holds the repository's code-health rules and pull-request quality gates. It exists
because every artifact in the tree arrived from a coding agent: the scaffold is a Next.js 16.3.4
`create-next-app` tree, the `/lab/context-engine` animation was rebuilt in-workspace from a Codex
HTML artifact that lived on another machine, the three `/lab/agent-delivery` diagrams are Archify
3.0.1 output, and Next 16 writes its own `AGENTS.md` (`<!-- BEGIN:nextjs-agent-rules -->`, generated
by `node_modules/next/dist/server/lib/generate-agent-files.js`) plus the one-line `@AGENTS.md`
import that was `CLAUDE.md` - both deleted in `daff7a5`, the same commit that set `agentRules: false`
in `next.config.ts`. The rules therefore describe agent failure modes only: every rule set keys off
a file path and a code-level metric, and `tag_codeowners_for_critical_code` is `false` in all four
gate maps, so no gate can depend on anything except the code in front of it.

The CLI is `cs` 1.0.55. Everything below is reproducible from the repository root:

```bash
export CS_ACCESS_TOKEN=$(cat ~/.codescene/token)
cs rules-config validate --config-path .codescene/code-health-rules.json --format json
cs rules-config validate --config-path .codescene/custom-quality-gates.json --format json
cs check-rules app/page.tsx
cs review --file-list <(git ls-files '*.ts' '*.tsx' '*.mjs') --output-format json
```

`cs` 1.0.55 reads `.ts`, `.tsx`, `.mjs`, `.js` and `.jsx` and nothing else here: 17 of the 37 tracked

`__tests__/` file, and no test runner in `package.json` (`dev`, `build`, `start`, `lint` only). Rather
than invent a test rule set that would match zero files, the `**/*` catch-all scores any future test
file at full weight - see *Test surface* below.

## Rule set order (first match wins, narrowest glob first)

`cs` evaluates `rule_sets` top to bottom and stops at the first `matching_content_path` that
matches, so the order is part of the design:

| # | `matching_content_path` | Treatment | Why this position |
| --- | --- | --- | --- |
| 1 | `public/diagrams/*.html` | all 23 rules `0.0` | generated by Archify 3.0.1; 41,112 of the repository's 41,853 source lines |
| 2 | `components/**` | all 23 rules `1.0`; file cap 200, function cap 90, max arguments 3 | narrower than `**/*`; the only directory with real control flow |
| 3 | `app/**` | all 23 rules `1.0`; file cap 90, function cap 60, max arguments 3 | narrower than `**/*`; route segments must stay thin |
| 4 | `**/*` | all 23 rules `1.0`, framework thresholds | catch-all last; a new directory starts strict |

## Per-rule-set rationale

### 1. Generated Archify exports (`public/diagrams/*.html`)

`distribution.html`, `repair-batch.html` and `ship-boundary.html` are Archify 3.0.1 output. Each
carries `<meta name="generator" content="archify 3.0.1">` on line 6, the SVG description on line 4992
reads "An architecture diagram generated by Archify." (distribution) or "A workflow diagram generated
by Archify." (repair-batch, ship-boundary), and `diagrams/README.md` states the contract: the editable
inputs are the JSON beside them and "editing generated HTML by hand will be lost on regeneration".

They are 13,678 / 13,711 / 13,723 lines and 753 / 754 / 758 KB. The three of them are 41,112 of the
41,853 lines across every tracked `.ts`/`.tsx`/`.mjs`/`.css`/`.html` file, so any size rule pointed
here measures Archify, not this site. All 23 rules are `0.0`: a diagram export is never a refactoring
target, and a size finding must not be "fixed" by hand-editing markup the next `finalize` run
overwrites.

`cs` 1.0.55 has no HTML analyzer - `cs review public/diagrams/ship-boundary.html` answers
`Unsupported file-type ".html"!` - so this set is a **declared boundary** today, not an active scoring
path. `cs check-rules public/diagrams/ship-boundary.html` already resolves the path to this file, and
the boundary is in force the moment an analyzer exists. To revise a diagram, re-run Archify
`finalize` with `diagrams/<name>.json` as the input and commit the regenerated HTML with it.

### 2. Client components (`components/**`)

The only directory in the repository with loops, conditionals and accumulating state: a canvas 2D
render loop with `requestAnimationFrame`, a `matchMedia` reduced-motion branch, an interval-driven
stage cycler and a `MotionConfig` provider. Nothing is muted - all 23 rules are `1.0` - and the
calibration is the thresholds, because the framework defaults never fire on a 164-code-line file that
`cs` already scores 10.0.

| Rule | Weight | What it catches here |
| --- | --- | --- |
| `Large Method` | `1.0` | the 112-code-line `ContextEngineCanvas.tick` (canvas `L80-202`), which draws grid, edges, particles, node labels and HUD in one body |
| `Bumpy Road Ahead` | `1.0` | the next per-node or per-reduced-motion special case inside the draw loop |
| `Deep, Nested Complexity` | `1.0` | a third nesting level in the particle or resize path |
| `Complex Method` | `1.0` | stage cycling that grows into arithmetic |
| `Code Duplication` | `1.0` | a local copy of `PIPELINE_STAGES` instead of the `lib/notebook-pipeline.ts` import |
| `Deep, Global Nested Complexity` / `Global Conditionals` | `1.0` | module-level browser capability checks becoming untestable |
| `Low Cohesion`, `Primitive Obsession`, `String Heavy Function Arguments` | `1.0` | left on deliberately: a component has one contract, its props object, so these do not misfire on `Stub({ title })` or `ContextEngineCanvas({ activeStageIndex })` |

Thresholds, each measured rather than assumed:

- `file_lines_of_code_for_warning` **200** - the canvas measures 164 code lines (`cs`: "This module
  has 164 lines of code (comments stripped away)") and scores 10.0 with no `.codescene/` present, so
  the default is at least 165 for this analyzer; 200 is the observed maximum plus roughly one more
  draw pass.
- `function_lines_of_code_warning` **90** - the measured component functions are
  `ContextEngineCanvas.tick` at 112 code lines and `ContextEngineLab` at 75 (`lab L9-89`). 90 falls
  between them: a component under 90 lines is still a view, and the 112-line closure is reported
  (`canvas 10.0 -> 9.38`, `Large Method`) instead of being allowed to pass until the default fires
  somewhere above 112.
- `function_max_arguments` **3** - a React component has one contract, its props object. No current
  component trips it.

### 3. App Router pages (`app/**`)

`layout.tsx` (33 lines) and eight route segments: `page.tsx` (63), `lab/page.tsx` (53),
`lab/agent-delivery/page.tsx` (73), `lab/context-engine/page.tsx` (11) and the four 5-line stubs
(`work`, `radar`, `library`, `digest`). Four stubs render `components/stub-page.tsx`, `/lab` and
`/lab/agent-delivery` are data tables plus JSX, and `/lab/context-engine` is an 11-line shell around
`ContextEngineLab`. That is the shape Next expects, which is why the cap is **tighter** here than in
`components/`: a route segment that starts fetching, shaping and interactively mutating in its own
body is the drift this set blocks, and the answer is a client component or a `lib/` module.

- `file_lines_of_code_for_warning` **90** - the largest pages measure 52 code lines (`app/page.tsx`)
  and 41 (`app/lab/agent-delivery/page.tsx`); 90 leaves both at 10.0 with room for one more section.
- `function_lines_of_code_warning` **60** - the largest route functions are `Home` at 52 code lines
  (`app/page.tsx L11-63`) and `AgentDeliveryPage` at 41 (`L33-73`); a page function past 60 lines has
  almost certainly absorbed a layout that should be an exported component.
- `function_max_arguments` **3** - a page takes its params object and a route handler takes
  `(request, context)`; a fourth positional argument means untyped plumbing.

All 23 rules are `1.0`, including the three class-shape and signature rules: with object-shaped props
they do not misfire, and leaving them on means a page that starts taking four positional strings says
so.

### 4. Catch-all (`**/*`)

Everything the sets above do not name: `lib/notebook-pipeline.ts` (77 lines of types and const
tables), the three config modules (`next.config.ts` 8 lines, `eslint.config.mjs` 18,
`postcss.config.mjs` 7), the JSON and Markdown `cs` cannot read, the five unreferenced Next.js
template SVGs under `public/`, and any directory a future change introduces - a `tests/` tree, a
`.github/` workflow, a second `lib/` module with real logic. All 23 rules are `1.0` with framework
thresholds for the detected language, so a new directory has to earn any relaxation with a measured
rule set of its own instead of inheriting one.

## Test surface

There is no test file today, so a dedicated test rule set would match zero paths. The standing
contract, recorded here so it is not improvised later, is the standard test profile: when a test glob
is added it goes **above** `**/*` and keeps `Bumpy Road Ahead`, `Deep, Nested Complexity`,
`Complex Method`, `Code Duplication`, `Large Assertion Blocks`, `Duplicated Assertion Blocks` and
`Lines of Code in a Single File` at `1.0`, while `Low Cohesion`, `Primitive Obsession` and
`String Heavy Function Arguments` go to `0.0` because they are class-shape and typed-signature metrics
that misfire on flat test modules.

Until then, a test file lands in `**/*` under **all 23 rules at 1.0** - including the three that the
test profile would zero. That is stricter than the profile, never looser, so nothing is hidden in the
meantime.

## Calibration ledger

Baseline is the 17 candidate files reviewed with no `.codescene/` present; post is the same 17 with
this rules file applied. 13 files are scorable in both runs; 4 return `"score": null` in both runs
because they declare no function body.

| Change | Where | Direction | Measured effect |
| --- | --- | --- | --- |
| 23 rules `0.0` | `public/diagrams/*.html` | exclude generated | none scorable today (`cs` rejects `.html`); the boundary is declared, and the three files are 41,112 of the repository's 41,853 source lines |
| `file_lines_of_code_for_warning` default -> 200 | `components/**` | tighten | none: the canvas is 164 code lines, still 10.0 |
| `function_lines_of_code_warning` default (>112) -> 90 | `components/**` | tighten | `components/lab/context-engine-canvas.tsx` 10.0 -> 9.38, `Large Method` on `ContextEngineCanvas.tick` (112 code lines, `L80-202`) |
| `function_max_arguments` default -> 3 | `components/**` | tighten | none: every component takes one props object |
| `file_lines_of_code_for_warning` default -> 90 | `app/**` | tighten | none: the largest page is 52 code lines |
| `function_lines_of_code_warning` default -> 60 | `app/**` | tighten | none: the largest route function is 52 code lines |
| `function_max_arguments` default -> 3 | `app/**` | tighten | none: every page takes at most its params object |

Aggregate over the 13 scorable files: mean **10.0000 -> 9.9523**, files below 10.0 **0 -> 1**, and
exactly one file changed. That single movement is the point of the layer: the largest function in the
repository is now reported instead of being allowed to pass because the default threshold sits above
it.

## Verification

```console
$ cs rules-config validate --config-path .codescene/code-health-rules.json --format json
{"status":"ok","summary":"Code health config is valid: 4 rule set(s), 92 rule override(s), 6 threshold override(s)."}

$ cs rules-config validate --config-path .codescene/custom-quality-gates.json --format json
{"status":"ok","summary":"Code health config is valid: 4 rule set(s), 0 rule override(s), 0 threshold override(s)."}
```

`cs check-rules` proves which paths a set covers. 1.0.55 prints only the config file that matched, so
the globs are proven by removing the catch-all and re-asking (a path that relies on `**/*` then
reports `No matching rule found`):

```console
$ cs check-rules components/lab/context-engine-canvas.tsx
Rule found in file: .codescene/code-health-rules.json
$ cs check-rules app/page.tsx
Rule found in file: .codescene/code-health-rules.json
$ cs check-rules public/diagrams/ship-boundary.html      # set 1, findable without the catch-all
Rule found in file: .codescene/code-health-rules.json
$ cs check-rules public/file.svg                         # set 1 does NOT match the SVGs
No matching rule found for public/file.svg
$ cs check-rules lib/notebook-pipeline.ts                # only the catch-all covers lib/
No matching rule found for lib/notebook-pipeline.ts
```

The last two lines are from a throwaway copy with `**/*` deleted, which is the only way this `cs`
build distinguishes "matched by a specialised set" from "matched by the catch-all".

First-match-wins was proven by inversion: with the `**/*` set moved to the top of a throwaway copy,
`cs review` returns 10.0 for all 13 scorable files, including the canvas - the broad set wins when it
is placed first, so the specialised sets win only because they precede it. The same copy with
`app/**`'s file cap lowered to 40 flags exactly the two app pages (41 and 52 code lines) and does not
flag the 164-line canvas, so no glob leaks into another.

## PR quality gates

`.codescene/custom-quality-gates.json` mirrors the four rule sets in the same order, and
`cs rules-config validate --config-path .codescene/custom-quality-gates.json --format json` returns
`{"status":"ok",...}`.

| # | `matching_content_path` | Gates |
| --- | --- | --- |
| 1 | `public/diagrams/*.html` | all six `false` - generator output, a regression here is an Archify version or input-JSON change |
| 2 | `components/**` | all six `true` - a new draw pass or effect is a whole-file health change |
| 3 | `app/**` | all six `true` - a page turning into an application is measured on the file it changed |
| 4 | `**/*` | all six `true` - no `pay_down_tech_debt` here, because with every scorable file at 10.0 there is no debt to pay |

`tag_codeowners_for_critical_code` is `false` in all four maps, the only match key any set carries is
`matching_content_path`, and no gate is conditional on who or what produced the diff: every gate
fires on the code in front of it.

## Maintenance protocol

1. A new first-party directory starts under `**/*` (all 23 rules on). Promote it to its own rule set
   only with a measurement in this file: `cs review` before and after, on every file in it.
2. Never widen a threshold to make a file pass. `ContextEngineCanvas.tick` is reported at 112 code
   lines; the answer is to split the draw passes, not to move the number.
3. Never hand-edit `public/diagrams/*.html`. Re-run Archify `finalize` with the matching
   `diagrams/<name>.json` and commit both files together.
4. When the first test file lands, add the test glob above `**/*` at the profile in *Test surface*
   and record the measurement here in the same change.
5. A `null` score means "not scored", not "clean": `lib/notebook-pipeline.ts` and the three config
   modules return `"score": null` before and after this configuration. Say so when quoting a number.
